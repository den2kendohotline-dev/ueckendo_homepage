\section{主な更新作業}

通常の運用で行う作業は、主に以下のとおりです。

\begin{itemize}
  \item NEWS（お知らせ）の追加・更新
  \item 部員情報の追加・変更

  \item 年間予定の更新
  \item Googleカレンダーによる稽古予定・大会予定の更新

\end{itemize}


% ========================================
\section{ホームページの構成}
% ========================================

\subsection{フォルダ構成}

ホームページのファイルは、以下のような構成になっています。

\begin{lstlisting}
kendo_homepage/
|
|-- css/
|   `-- style.css
|
|-- images/
|   |-- main.jpg
|   |-- members-bg.png
|   `-- ...
|
|-- js/
|   `-- main.js
|
|-- .gitignore
|-- homepage.tex
|-- index.html
`-- news.html
\end{lstlisting}


\subsection{各ファイルの役割}

\begin{longtable}{p{0.27\textwidth}p{0.63\textwidth}}

\toprule
\textbf{ファイル・フォルダ} & \textbf{役割} \\
\midrule
\endhead

\texttt{index.html}
&
ホームページ本体です。
ABOUT、NEWS、SCHEDULE、MEMBERS、RESULTS、CONTACTなど、
トップページに表示される内容を記述しています。
\\

\texttt{news.html}
&
過去のお知らせを含むNEWS一覧ページです。
新しいお知らせを追加するときに編集します。
\\

\texttt{css/style.css}
&
ホームページ全体のデザインを管理しています。
文字サイズ、色、余白、スマートフォン表示、
部員カードなどの見た目を変更するときに編集します。
\\

\texttt{js/main.js}
&
ホームページの動作を管理しています。
部員カードのスライド、スマートフォン用メニュー、
ヘッダーの動作、試合結果ページ等への遷移時の
ローディング処理などが記述されています。
\\

\texttt{images/}
&
トップページやMEMBERS欄などで使用する画像を保存します。
\\

\texttt{homepage.tex}
&
本引継ぎマニュアルのLaTeXファイルです。
ホームページの仕様や運用方法を変更した場合は、
必要に応じてこの資料も更新してください。
\\

\bottomrule

\end{longtable}


\subsection{普段編集するファイル}

通常のホームページ運用では、主に

\begin{itemize}
  \item \texttt{index.html}
  \item \texttt{news.html}
\end{itemize}

を編集します。

\texttt{style.css} と \texttt{main.js} は、
ホームページのデザインや動作そのものを変更するときに使用します。\\
通常のお知らせ追加や部員情報の更新では、
基本的にこれらを変更する必要はありません。

\section{作業を始める準備}
% ========================================

ホームページと試合結果アプリは、
それぞれ別のGitHubリポジトリで管理しています。

\begin{itemize}
  \item ホームページ本体：\texttt{kendo\_homepage}
  \item 試合結果・MEMBERS ONLY：\texttt{kendo\_web\_app}
\end{itemize}

新しいPCで初めて作業する場合は、
最初に両方のリポジトリをGitHubから取得します。\\
この作業は、基本的にPCごとに最初の1回だけ行います。

\subsection{GitHubにログインする}

まず、ブラウザからGitHubを開き、 
ホームページの管理に使用しているGitHubアカウントにログインしてください。
メールアドレスは電通大剣道部ので、パスワードは「ueckendow」です。

\subsection{Gitを確認する}

PCにGitがインストールされていることを確認します。\\
PowerShellを開き、以下を実行してください。

\begin{lstlisting}
git --version
\end{lstlisting}

バージョン情報が表示されればGitを使用できます。


\subsection{GitHubからファイルを取得する}

GitHub上の
\texttt{kendo\_homepage} と
\texttt{kendo\_web\_app} のリポジトリを開き、
それぞれのリポジトリURLをコピーします。\\
次に、PowerShellで保存したい場所へ移動します。\\
作成時のPCでは、

\begin{lstlisting}
C:\Users\ryota\projects
\end{lstlisting}

に保存しています。

\begin{lstlisting}
cd C:\Users\ryota\projects
\end{lstlisting}

その後、それぞれのリポジトリを取得します。

\begin{lstlisting}
git clone kendo_homepageのGitHubリポジトリURL
git clone kendo_web_appのGitHubリポジトリURL
\end{lstlisting}

これにより、作業用のフォルダとして

\begin{lstlisting}
C:\Users\ryota\projects\kendo_homepage
C:\Users\ryota\projects\kendo_web_app
\end{lstlisting}

の2つが作成されます。\\
引継ぎ後は、それぞれのPCで保存した場所に
読み替えてください。


\subsection{作業するディレクトリ}

ホームページ本体を更新するときは、

\begin{lstlisting}
cd C:\Users\ryota\projects\kendo_homepage
\end{lstlisting}

を実行します。\\
試合結果、選手情報、MEMBERS ONLY、
試合動画などを更新するときは、

\begin{lstlisting}
cd C:\Users\ryota\projects\kendo_web_app
\end{lstlisting}

を実行します。\\
2つは別のGitリポジトリなので、
更新する内容に応じて作業するディレクトリを変更してください。\\
初めてGitHubへ変更を送信するときに
ログインや認証を求められた場合は、
画面の案内に従って認証してください。


% ========================================
\section{NEWS（お知らせ）の更新}
% ========================================

\subsection{NEWSの仕組み}

NEWSは、

\begin{enumerate}
  \item トップページのNEWS欄
  \item NEWS一覧ページ
\end{enumerate}

の2か所に表示されます。

トップページ側は \texttt{index.html}、
一覧ページ側は \texttt{news.html} で管理しています。\\
新しいお知らせを掲載するときは、
両方のファイルを更新します。\\
トップページの \texttt{index.html} には最新3件を表示し、
\texttt{news.html} には過去のお知らせも残します。


\subsection{トップページにNEWSを追加する}

\texttt{index.html} を開き、

\begin{lstlisting}
<div class="news-list">
\end{lstlisting}

の中にある既存のNEWSを確認します。\\
1件のお知らせは、以下のような形式です。

\begin{lstlisting}[language=HTML]
<article class="news-item">
  <p class="news-date">2026.09.20</p>
  <p class="news-title">
    第75回関東学生剣道優勝大会が開催されましたので、
    結果をアップしました。
  </p>
</article>
\end{lstlisting}

新しいお知らせを追加する場合は、
既存の \texttt{article} をコピーして、
日付と文章を変更してください。\\
新しいお知らせは一番上に追加します。
トップページは最新5件のみ表示するため、
6件になった場合は一番古いお知らせを
\texttt{index.html} から削除してください。\\
削除したお知らせは
\texttt{news.html} には残します。


\subsection{NEWS一覧ページにも追加する}

次に \texttt{news.html} を開きます。\\
現在は、年ごとに

\begin{lstlisting}[language=HTML]
<div class="news-year">
  <h2>2026</h2>

  <div class="news-list">
    ...
  </div>
</div>
\end{lstlisting}

という形でNEWSを管理しています。\\
同じ年のお知らせであれば、
その年の \texttt{news-list} の一番上に追加してください。


\subsection{年が変わった場合}

新しい年になった場合は、
新しい \texttt{news-year} を作成します。\\
例えば2027年の場合は、

\begin{lstlisting}[language=HTML]
<div class="news-year">
  <h2>2027</h2>

  <div class="news-list">
    <!-- 2027年のお知らせ -->
  </div>
</div>
\end{lstlisting}

を2026年のNEWSより上に追加します。

\section{部員情報の更新}
% ========================================

\subsection{部員情報の場所}

部員情報は \texttt{index.html} の
MEMBERSセクションで管理しています。\\
部員は学年ごとに分けられており、

\begin{lstlisting}[language=HTML]
<div class="grade-block">
\end{lstlisting}

が1つの学年を表します。\\
その中に、各部員の

\begin{lstlisting}[language=HTML]
<article class="member-card">
\end{lstlisting}

が並んでいます。


\subsection{部員カードの構造}

部員1人分は、以下のような形式です。

\begin{lstlisting}[language=HTML]
<article class="member-card">

  <p class="member-role">主将</p>

  <h4>山田 太郎</h4>

  <dl>

    <div>
      <dt>所属学類</dt>
      <dd>II類</dd>
    </div>

    <div>
      <dt>段位</dt>
      <dd>三段</dd>
    </div>

    <div>
      <dt>出身高校</dt>
      <dd>○○高等学校</dd>
    </div>

  </dl>

</article>
\end{lstlisting}

新しい部員を追加するときは、
既存のカードを1つコピーし、
必要な情報を書き換えてください。


\subsection{役職がない場合}

役職がない部員についても、
レイアウトをそろえるため、
既存の役職がない部員のカードと同じ形式にしてください。


\subsection{年度替わり}

年度が変わった際には、MEMBERSについて以下を確認します。

\begin{enumerate}
  \item 各学年を1つ上げる
  \item 新1年生の欄を作成する
  \item 新入部員のカードを追加する
  \item 主将、主務、会計などの役職を変更する
  \item 段位に変更がある場合は更新する
  \item 卒業した部員の表示を整理する
\end{enumerate}

\section{Git・GitHubによる更新}
% ========================================

ホームページのファイルを編集した後は、
Gitを使用して変更内容をGitHubへ反映します。\\
GitHubへpushすると、
Renderが変更を検出し、公開サイトへ自動的に反映されます。


\subsection{作業ディレクトリへ移動する}

PowerShellを開き、ホームページの作業ディレクトリへ移動します。\\
作成時のPCでは、

\begin{lstlisting}
cd C:\Users\ryota\projects\kendo_homepage
\end{lstlisting}

を実行します。\\
引継ぎ後は、それぞれのPCで
\texttt{kendo\_homepage} を保存した場所に読み替えてください。


\subsection{変更内容をGitに追加する}

ファイルを変更したら、

\begin{lstlisting}
git add .
\end{lstlisting}

を実行します。


\subsection{コミットする}

次に、変更内容をコミットします。

\begin{lstlisting}
git commit -m "update"
\end{lstlisting}

\texttt{"update"} の部分はコミットメッセージです。\\
内容は自由ですが、
変更内容が分かるものにしておくと後から確認しやすくなります。


\subsection{GitHubへpushする}

コミット後、

\begin{lstlisting}
git push
\end{lstlisting}

を実行します。\\
これでPC上の変更がGitHubへ送信されます。

\subsection{基本的な更新手順}

普段は、以下の流れで更新します。

\begin{lstlisting}
git add .
git commit -m "update"
git push
\end{lstlisting}

GitHubへpushした後は、
公開サイトを開いて変更内容が反映されていることを確認してください。

\section{Renderへのデプロイ}
% ========================================

\subsection{Renderの役割}

ホームページはRenderを使用して公開しています。\\
GitHubのリポジトリとRenderが接続されているため、
通常はGitHubへpushすると、
Renderが変更を検出して自動的にデプロイします。\\
そのため、通常の更新では
Render上で毎回ファイルをアップロードする必要はありません。


\subsection{公開後の確認}

デプロイが完了したら、

\begin{center}
\url{https://ueckendo-homepage.onrender.com/}
\end{center}

を開き、変更内容が正しく反映されていることを確認してください。

\section{YouTube動画の更新}
% ========================================

試合動画はYouTubeにアップロードし、
MEMBERS ONLYページから閲覧できるようにしています。
YouTubeへの動画のアップロード方法については、
別途作成されているYouTube用マニュアルを参照してください。

\texttt{kendo\_web\_app} の

\begin{lstlisting}
templates/members_videos.html
\end{lstlisting}

\subsection{大会動画を追加する}

\texttt{members\_videos.html} を開き、
既存の大会動画の部分をコピーして使用します。

\begin{lstlisting}[language=HTML]
<div class="video">
  <div class="date">2026.09.13</div>

  <div class="name">
    第75回関東学生剣道優勝大会
  </div>

  <a
    class="watch"
    href="YouTubeのURL"
    target="_blank"

コピーした後、以下の3か所を変更します。

\begin{itemize}
  \item \texttt{date}：大会の日付
  \item \texttt{name}：大会名
  \item \texttt{href}：YouTubeの動画またはプレイリストのURL

新しい大会は、
同じ年度の中で新しいものが上になるように追加してください。

\section{Git・GitHubによる更新}
% ========================================

\texttt{kendo\_web\_app} のファイルを変更した後も、
ホームページ本体と同様にGitを使用してGitHubへ反映します。\\
PowerShellで
\texttt{kendo\_web\_app} のディレクトリへ移動してから、

\begin{lstlisting}
git add .
git commit -m "update"
git push
\end{lstlisting}

を実行します。\\
\texttt{kendo\_homepage} と
\texttt{kendo\_web\_app} は別のGitリポジトリなので、
別々にpushします。
GitHubへpushすると、
Renderが変更を検出して自動的にデプロイします。\\
デプロイ後は実際のページを開き、
変更内容が正しく反映されていることを確認してください。
